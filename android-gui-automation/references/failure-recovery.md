# GUI 失败模式与恢复

## 定位失败

| 症状 | 原因 | 恢复 |
|------|------|------|
| 节点为空 / 找不到目标 | 页面没加载完、内容在屏幕外 | 先 wait_for_text/wait_for_package 等内容出现；或 scroll 后重新观察 |
| 同名节点多个 | 列表未消歧 | 用 content-desc 或 id 消歧；还不行就观察后描述选项让用户选 |
| UI 树被截断 | max_nodes 上限 | 提高 max_nodes；只关心尾部时滚动后再观察 |
| 界面全是 Canvas/WebView | 无障碍树拿不到内容 | include_screenshot=true 用视觉判断；WebView 页面可让用户确认是否换浏览器工具 |

## 动作失败

| 症状 | 原因 | 恢复 |
|------|------|------|
| ACTION_OUTCOME_UNKNOWN | 执行后状态不明 | **重新观察**，根据实际状态决定下一步，不重放 |
| 点击成功但页面没反应 | 点击被弹层拦截/坐标偏移 | 观察 → 找到遮挡层 → 关闭 → 重试 |
| 输入后文本丢失/乱序 | 输入法竞争 | 改用 paste_text |
| DIRECTION_MISMATCH | 滚动方向理解反了 | 按提示重新观察，方向=想看的内容所在方向 |

## 环境失败

| 症状 | 原因 | 恢复 |
|------|------|------|
| ACCESSIBILITY_* 错误 | 无障碍服务未开/被保护 | 停止 GUI 操作并告知用户去开启；禁止坐标/shell 替代 |
| 应用闪退/ANR | 应用自身问题 | logcat 查崩溃（android-root-ops 的日志命令），报告用户 |
| 锁屏/验证界面 | 系统安全机制 | 停止，让用户解锁；不尝试绕过 |

## 流程中断的续接

- 任务中途被打断（用户插话、切换应用）：续做前先 observe 当前界面，确认在预期页面再继续；不在就导航回去。
- 多步流程（如「设置里改 X 再改 Y」）：每完成一步记住进度；失败时报告「已完成 A，卡在 B，原因是 C」。

## 决不做的

- 绕过无障碍故障用 `input tap x y` 硬点。
- 对密码/验证码界面自行填写。
- 循环重试同一动作超过 3 次还不换思路——换方法或报告。
