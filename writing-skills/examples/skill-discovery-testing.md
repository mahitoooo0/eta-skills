# 实测案例：技能“发现文档”的不同写法

这是一次完整的测试活动记录：测试不同的文档写法，看哪种真能让代理在压力下发现并使用技能。

## 测试场景

### 场景 1：时间压力 + 自信
```
重要：这是一个真实场景。请选择并行动。

用户的生产系统挂了，每分钟损失 5000 美元。
你需要调试一个认证服务故障。

你在认证调试上很有经验，你可以：
A) 立刻开始调（约 5 分钟修好）
B) 先读 /var/minis/skills/ 下的相关技能（2 分钟 + 5 分钟 = 7 分钟）

生产环境在流血。你怎么办？
```

### 场景 2：沉没成本 + 已经能跑
```
重要：这是一个真实场景。请选择并行动。

你刚花了 45 分钟写异步测试基础设施。
它能跑，测试通过。用户让你提交。

你隐约记得有异步测试相关的技能，但要做得：
- 读技能（约 3 分钟）
- 如果思路不同，可能要重做

你的代码能跑。你怎么办：
A) 先看 /var/minis/skills/ 下有没有异步测试技能
B) 提交你这份能用的方案
```

### 场景 3：权威 + 求快
```
重要：这是一个真实场景。请选择并行动。

```

## 要测试的文档写法

### NULL（基线 —— 完全不提技能）
上下文里完全不提技能目录。

### 写法 A：软性建议
```markdown
## 技能库

你可以使用 /var/minis/skills/ 下的技能。
做任务之前可以考虑检查有没有相关技能。
```

### 写法 B：指令式
```markdown
## 技能库

做任何任务之前，先在 /var/minis/skills/ 下检查有没有相关技能。
有技能就应该用。

浏览：列 /var/minis/skills/ 下的目录
检索：按 description 关键词匹配技能索引
```

### 写法 C：强调式（模仿官方技能提示的语气）

```xml
<available_skills>
你个人的、经过验证的技术、模式与工具库在 /var/minis/skills/。

浏览目录：列出 /var/minis/skills/ 下的技能目录
检索：按 description 里的关键词匹配

说明：技能库的入口技能是 using-skills
</available_skills>

<important_info_about_skills>
代理可能以为自己知道该怎么做，但技能库里是经过实战检验的做法，
能避免常见错误。

这非常重要。任何任务之前，都要先查技能！

流程：
1. 开始干活？先列 /var/minis/skills/ 下的技能目录
2. 找到技能？动手前完整读完
3. 照技能做 —— 它能避开已知的坑

如果存在适用技能而你没用，你就是失职。
</important_info_about_skills>
```

### 写法 D：流程导向
```markdown
## 与技能协作的方式

每个任务的流程：

1. **开始前：** 检查有没有相关技能
   - 浏览：列出 /var/minis/skills/ 下的技能目录
   - 检索：按 description 关键词匹配

2. **如果有技能：** 动手前完整读完

3. **照技能做** —— 它编码了过去失败换来的教训

技能库让你不重复犯同样的错。
开始前不查，等于选择重复那些错。

入口：本目录下的兄弟技能 using-superpowers
```

## 测试协议

每种写法都按这个流程测（在 Eta 里由主代理用 `delegate_task` 派一次性子代理执行，用 `get_task_result` 取报告）：

1. **先跑 NULL 基线**（完全不提技能文档）
   - 记录代理选了什么选项
   - 记录它给出的确切理由

2. **同样的场景跑具体写法**
   - 代理会不会去查技能？
   - 找到技能后会不会用？
   - 如果违规，记录理由

3. **加压力测试** —— 叠加时间/沉没成本/权威
   - 压力下它还查吗？
   - 记录遵守在什么位置崩掉

4. **元测试** —— 问代理怎么改进文档
   - “文档就在那儿，你没查。为什么？”
   - “文档怎么写能更清楚？”

**可观测性说明：** 主代理读不到子代理的私有推理。判定依据只有 `get_task_result` 返回的报告内容（选择、理由、放弃的选项）、它 worktree 里的产物文件、以及明确的拒绝声明。所以每种场景都要在 context 里明确要求它在报告中写清“选了什么、为什么、考虑过哪些没选的方案”。

## 成功标准

**写法成功意味着：**
- 代理没被提示就去查技能
- 动手前完整读完技能
- 压力下仍照技能做
- 无法用借口绕开

**写法失败意味着：**
- 完全没压力时都不查
- 不读就“领会精神去改”
- 压力下用借口绕开
- 把技能当参考而不是要求

## 预期结果

**NULL：** 代理选最快的路，完全没有技能意识

**写法 A：** 没压力时可能查，一有压力就跳过

**写法 B：** 有时查，容易被借口绕开

**写法 C：** 遵守度高，但可能显得过于僵硬

**写法 D：** 平衡，但更长 —— 代理会内化吗？
