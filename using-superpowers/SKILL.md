<SUBAGENT-STOP>
如果你是被派发来执行某个具体任务的子代理，忽略本技能。
</SUBAGENT-STOP>

<EXTREMELY-IMPORTANT>
只要你认为某个技能有哪怕 1% 的可能适用于你正在做的事，你就必须加载它。

如果某个技能适用于你的任务，你没有选择。你必须用它。

这不可协商。你不能用任何理由把自己绕过去。
</EXTREMELY-IMPORTANT>

## 规则

**在任何回复或行动之前加载相关或被要求的技能** —— 包括澄清提问、翻看代码库、检查文件。如果读完发现不适用，你可以不用它。

**在给出执行计划之前：** 如果还没做过头脑风暴，先读本目录下的兄弟技能 brainstorming。

然后声明"使用 [技能] 来完成 [目的]"，并严格照它执行。如果技能带清单，就在你的回复里为每一项建一条编号待办（Eta 没有 todo 工具，清单直接写在回复里，完成一项就更新一项）。

## 技能优先级

多个技能同时适用时，流程类技能优先 —— 它们定方法，随后由实现类技能落地。头脑风暴（brainstorming）与系统化调试（systematic-debugging）是最常用的流程类技能，但这条规则适用于所有流程类技能。

- "我们来做个 X" → 先读兄弟技能 brainstorming，再用实现类技能。
- "修这个 bug" → 先读兄弟技能 systematic-debugging，再用领域技能。

## 在 Eta 上如何落地"加载技能"

- 技能目录是 `/var/minis/skills/<skill-id>/`，每个技能一个 `SKILL.md`。
- 每轮对话开始时，**先看当轮上下文注入的技能索引**：索引列出当前可用技能及其触发条件。命中就打开该技能目录下的 `SKILL.md` 正文，再动手。
- 索引里没列出、但你判断相关的技能，仍然按名称找到它的目录并读正文；不要凭记忆复述技能内容。
- 读正文、按正文执行。技能会演进，记忆里的版本不算数。
- Eta 不使用其它 harness（Claude Code、Codex、Pi、Gemini CLI 等）的工具映射；本技能只按本文件的正文执行，平台事实以仓库根的 ADAPT.md 为准，不要凭旧平台经验补工具名。
- Eta 没有计划模式、没有斜杠命令、也没有待办工具。要给的"计划"就是你在回复里写出的计划，等用户确认；要跟踪的待办就是回复里的编号清单。

## 红旗信号

出现这些念头就停下——你在给自己找借口：

| 念头 | 现实 |
|------|------|
| "这只是个简单问题" | 提问也是任务。先查技能。 |
| "我得先多点上下文" | 查技能在澄清提问之前。 |
| "让我先翻翻代码库" | 技能会告诉你该怎么翻。先查。 |
| "我可以快速看一眼文件/git" | 文件里没有对话上下文。先查技能。 |
| "让我先收集信息" | 技能会告诉你该怎么收集。 |
| "这不需要正式技能" | 只要技能存在，就用它。 |
| "我记得这个技能" | 技能会演进。读当前版本。 |
| "这不算一个任务" | 行动 = 任务。先查技能。 |
| "用技能是杀鸡用牛刀" | 简单的事会变复杂。用它。 |
| "我就先做这一件事" | 做任何事之前先查。 |
| "这样感觉很有产出" | 没有纪律的行动是在浪费时间。技能就是防这个的。 |
| "我知道那是什么意思" | 懂概念 ≠ 用了技能。加载它。 |

## 用户指令

用户指令（Eta 的 MEMORY.md、当轮上下文里的用户直接要求）优先于技能，技能优先于默认行为。只有当用户明确让你跳过时，才跳过技能流程或指令。
