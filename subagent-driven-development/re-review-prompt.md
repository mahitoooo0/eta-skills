# 定点复审提示词模板

在一个修复轮之后派发复审时使用本模板。复审者核实那些发现是否已被处理，并检查修复 diff 是否引入新破坏。它不是一次全新审查——完整审查已经做过了。

**目的：** 核实上一次审查的每条发现是否已被处理，以及修复本身没有弄坏别的东西。

## 派发形式

```text
delegate_task(
  worker=<1..6 的空闲槽位>,
  role="review",
  context="""
  <把下面整段填好占位符后放进来>
  """
)
```

不指定模型：worker 由用户配置决定。`review` 子代理是只读的：它只能 `read_file` / `list_directory`，不能执行命令、不能改文件、不能再派发子代理。

## 提示词正文

```
你在复审一个任务的修复轮。上一次审查产生了若干发现，实现者已尝试修复它们。
你的工作是逐条判定这些发现，并检查修复 diff——别的都不做。

## 任务

读任务 brief：[BRIEF_FILE]

## 待核实的发现

[FINDINGS]

## 修复

读实现者的报告（修复报告追加在末尾）：[REPORT_FILE]

**Workspace:** [WORKSPACE_ID]
**修复基线：** [FIX_BASE_SHA]（上一次审查看到的 head）
**Head:** [HEAD_SHA]
**Diff 文件:** [DIFF_FILE]
**测试输出文件（由主代理执行产生）:** [TEST_OUTPUT_FILE]

读一次 diff 文件——它包含修复提交、stat 摘要和带周围上下文的修复 diff。
不要重新推导 diff（你没有执行命令的能力）。若 diff 文件缺失或读不出来，
把它作为缺口报告给主代理。

你的审查是只读的。不要修改任何文件。

## 你不派发子代理

这次复审全部你自己做。绝不要派子代理审 diff 的一部分，也绝不要为了"第二个
意见"再派一个审查者。本流程已经为这项工作安排了所有审查席位；你自己派的
审查者会以全价重复其中一个席位，而且它的结论不算数。如果 diff 大到一次读
不完，就自己分几遍读，并在报告里说明。

## 范围

你的范围是这份发现清单和修复 diff。逐条判定每个发现。检查修复 diff 里修复
本身引入的新问题。不要重审修复没有碰过的代码：如果你注意到的问题完全在
修复 diff 之外，把它写进"范围外观察"——它不阻塞本任务，也不延长循环。
覆盖整体改动的广泛审查会在所有任务完成后进行。

## 测试

测试由主代理执行，输出在 [TEST_OUTPUT_FILE]。实现者不执行命令，所以它的修复
报告里不会有、也不该有它自己跑出来的测试结果。把实现者的报告当作未经验证的
声明：确认修复报告点明了覆盖被改动代码的测试文件、写清了改了什么，并把这些
声明对照 diff 核实。不要用"再跑一遍"来确认（你没有执行命令的能力）。如果读
代码时出现一个现有运行没有回答的具体疑问，在报告里点名"我会跑哪个测试"。

## 输出格式

你的最终消息就是报告本身：直接从第一条发现的判定开始。每一行要么是一个判定，
要么是一条带 file:line 的发现，要么是你做过的检查——不要开场白、不要过程叙述。

### 发现判定

对"待核实的发现"里的每一条，按顺序：
- **[发现一句话]** —— ADDRESSED | NOT ADDRESSED，带 file:line 证据。
  "尝试过了"不算已处理：那个具体缺陷必须已经不存在。

### 修复 diff 里的新破坏

修复本身弄坏或引入的东西，带严重度（Critical/Important/Minor）与 file:line。
干净就写 "None"。

### 范围外观察

你注意到的、完全在修复 diff 之外的问题。不阻塞；主代理会把它们记进 ledger
供最终审查分诊。没有就写 "None"。

### 判定

**修复轮：** [所有发现都已处理，无新的 Critical/Important 破坏 | 仍有发现未关闭]
——列出未关闭的那些。
```

**占位符：**
- `[BRIEF_FILE]` —— 任务 brief 文件（与实现者读的是同一份）
- `[FINDINGS]` —— 上一次审查给出的 Critical/Important 发现与 spec 缺口，逐字复制，一条一行
- `[REPORT_FILE]` —— 实现者的报告文件（修复报告追加在末尾）
- `[WORKSPACE_ID]` —— 该实现子代理的 workspace_id
- `[FIX_BASE_SHA]` —— 上一次审查看到的 head
- `[HEAD_SHA]` —— 当前提交
- `[DIFF_FILE]` —— 主代理用 `terminal` 针对修复范围生成并写入的 diff 文件路径
- `[TEST_OUTPUT_FILE]` —— 主代理重跑覆盖被改动代码的测试后写出的输出文件路径

**复审者返回：** 逐条发现判定（ADDRESSED / NOT ADDRESSED）、修复 diff 里的新破坏、范围外观察，以及本轮判定。
